jsonwebtoken — Algorithm-Confusion Check

// jwt.verify() with NO `algorithms` option -- jsonwebtoken@9 default behavior
jwt.verify(forgedHS256Token, rsaPublicKey);
// -> REJECTED: "invalid algorithm". The classic RS256->HS256 attack is
//    already mitigated by default. Correct library behavior, not a bug.

Not a library vulnerability — an edge case worth knowing: that default protection depends on the key still parsing as a real key. If its PEM BEGIN/END envelope markers are lost (confirmed by the maintainer: internal line breaks don't matter, but the envelope lines always must be present — auth0/node-jsonwebtoken#669), verification falls back to treating the value as a plain secret. That's not a quiet backdoor, though: a real user's own legitimate token fails the exact same way in that state, so it surfaces as a total login outage, not a hidden exploit. Pin { algorithms: ['RS256'] } explicitly anyway — cheap, unconditional defense-in-depth either way.

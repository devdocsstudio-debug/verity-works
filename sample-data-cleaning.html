A CSV Cleaning Pipeline Whose Real Output Is the Rejection Report

Zero dependencies, Node built-ins only. Nothing is changed silently and nothing is discarded silently — every normalisation is recorded, and every row that cannot be cleaned is rejected with a reason.

Sample scope note: this is an independent portfolio sample published by DevDocs Studio, the technical service from Verity Works, to show how we work. It is not client work and was not commissioned. The input is synthetic: invented businesses, 555 phone numbers, and domains under the .example TLD that RFC 2606 reserves for documentation and which can never be registered. No real personal data appears anywhere in it. Last verified run: 14/14 tests passing; 10 rows in, 4 accepted, 6 rejected, 25 fields normalised.

The principle

A cleaner that guesses is worse than one that refuses, because the guess arrives in the file looking exactly like data. 555-0233 is a seven-digit phone number; padding it into something dialable would be inventing a fact about a business.

So the pipeline emits two artifacts, and the second one is the point:

cleaned.csvthe rows that passed, normalised
report.jsonevery change made, every row rejected, and why

The duplicate only normalisation can find

Lines 2 and 3 differ in leading whitespace, email case, state case, phone format and revenue formatting — five surface differences. They are the same business.

  Acme Plumbing LLC ,John Smith,JOHN@ACME-PLUMBING.EXAMPLE,(303) 555-0142,denver,CO,1998,"$1,200,000"
Acme Plumbing LLC,John Smith,john@acme-plumbing.example,303-555-0142,Denver,co,1998,"1200000"

Deduplication runs after normalisation, which is the only order in which it finds them — and the collapse is reported rather than silent.

Normalisations

emailJOHN@… → lowercased; an address with no dotted TLD is rejected, not silently kept
phone(303) 555-0142, 303-555-0142, +1 303 555 0177 → E.164. Seven digits is reported, never padded
revenue$1,200,000, 1200000, $2.1M → integer dollars. $0 is kept, because a legitimate zero is not missing data
foundedrange-checked 1800–2026, so 2200 is rejected rather than stored
state / citycolorado, co → CO; denver → Denver
websitebare host gains https; http is upgraded

The tests that would catch a regression still looking correct

Most of the 14 are per-field. Four are invariants, and those are the ones worth reading:

  • Every difference between input and output appears in the report — the tool's whole promise.
  • Every rejected row states a reason, and never reaches the output.
  • Counts reconcile: accepted + rejected = rows in. A row cannot go missing unreported.
  • Idempotent: re-running on the cleaned output changes nothing. A cleaner that keeps “fixing” its own output will eventually corrupt a field.
